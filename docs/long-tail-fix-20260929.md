# Rust 长尾优化与实测（0.4.18）

最终版本 0.4.18 已部署到 `market-mirror.feng.dog`（192.0.2.40）。部署完成时间：2026-09-29T10:22:45.868685+00:00；完整就绪 2470/2470，部署前后核对 24,496 根已收盘 K 线，无差异、无缺失币种。Java 服务、线上配置和磁盘格式未修改。

已建立的全市场价格快照过期后，请求不再等待后台 REST 锁。后台从启动起维护快照，空闲刷新目标 2 秒、活跃目标 500ms；价格刷新等待 1 秒后可使用有界预留额度。总分钟配额、Binance 冷却、10 秒 REST 基线期限与 250ms 编码期限继续生效。

新币初始化、连接恢复优先于例行订正；普通 worker 全部阻塞时，最多增加一个恢复任务。`/health/ready` 保留完整订阅检查，`/health/serving` 在首次完整就绪后检查已投入服务的序列；启用 strict_readiness 的 bulk 按请求币种与周期检查。生产仍使用 strict_readiness=false。

K 线补零仍要求上一根真实 WebSocket `x=true`；查询没有新增 K 线 REST 补齐。完全冷启动和需要补建币种排序的多币价格请求保留原有有界初始化路径，上游持续异常超过期限时仍会明确返回不可用。

## 资源占用

与常规复测时间窗对齐。CPU 的 100% 代表一个核；RSS 是窗口平均。

| 指标 | Rust 前测 | Rust 后测 | Java 同期后测 |
|---|---:|---:|---:|
| 应用 CPU | 20.53% | 15.79% | 12.99% |
| RSS | 626.62 MiB | 526.46 MiB | 1442.42 MiB |
| 主机 CPU steal | 2.49% | 1.08% | 0.03% |

这次主要优化排队与可用性。CPU 是否下降以表中结果为准；重启后的较低 RSS 不能直接归因为内存优化。Java 同期仍有额外生产请求，比较不代表两端总负载相同。

同一常规窗口内，Rust 的 WebSocket aggTrade 计数增量为前测 91,473、后测 47,876。CPU 差异同时受到行情消息量与主机 steal 变化的影响，不能全部归因于本次代码改动。

后台全市场价格 REST 排队日志（同一常规窗口内完成的请求，毫秒）：

| 市场 | 前测 p99 / 最大值 | 后测 p99 / 最大值 |
|---|---:|---:|
| 现货 | 493.16 / 3980.93 | 1001.21 / 1001.23 |
| 合约 | 1665.85 / 1925.58 | 1000.58 / 1001.44 |
