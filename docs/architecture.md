# 架构与业务兼容性

## 热路径

```mermaid
flowchart LR
    WS[WebSocket 帧] --> Wire[直接解析为数值和借用标识]
    Wire --> Catalog[不可变目录映射为序列 ID]
    Catalog --> State[单序列有界环形缓存]
    State --> Notify[最终状态通知]
    HTTP[HTTP bulk] --> Flight[相同请求共享任务]
    Flight --> Wait[按请求涉及的序列等待]
    Notify --> Wait
    Wait --> Copy[短读锁复制所需记录]
    Copy --> Encode[限并发编码工作线程]
    Encode --> Cache[有界响应字节缓存]
    Cache --> HTTP
```

缓存优先处理最新记录，更新和追加通常 O(1)；历史修订二分查找，插入移动成本由保留容量限制。每条记录包含数值、最终标记和流版本，避免跳表节点、装箱数值以及三个容器间的状态维护。

WebSocket 读取任务直接解析和提交一帧，不创建每帧任务或无界队列；每 64 帧主动让出执行权。没有刻意丢弃形成中消息。HTTP 大响应编码最多同时执行 2 个任务，避免占用网络与计时器执行线程。读取缓存后即释放锁，编码和任何 await 都不持有序列锁。

`kline-runtime` 在外围组合 REST、时钟、持久化和就绪检查。REST 与恢复也通过同一个 `Engine::commit` 发布数据；持久化从短读锁内复制最终记录，随后在锁外编码和写盘。service 通过 `Readiness` 接口读取状态，不依赖 runtime 的实现。[生命周期细节](runtime.md)。

## 状态规则

1. 最终记录不能被形成中记录覆盖。
2. 第一条流式最终记录有权修正交易数更高的形成中记录；已有最终记录拒绝更低的交易数。
3. 交易数相同时，依据事件时间及接收序号判断新旧；事件时间缺失、为零和接收序号缺失分别处理。
4. REST、restore、synthetic 与流更新使用同一个提交规则；restore/synthetic 不覆盖同交易数记录，REST 不覆盖相同交易数的流版本。
5. 最终修订、REST/恢复补齐最终历史触发缓存版本变更。保留容量之外的旧数据不会重新生成孤立标记或版本。

Rust 使用严格容量上限。Java 的实现会在 `minMaintainCount + 50` 后批量裁剪；两者提供相同的最低历史深度，但不保证保留额外缓冲记录的数量相同。

## bulk 规则

- 默认 limit=5，裁剪到 1–100。交易对去空、去重、排序，大小写不自动转换。
- `closed_only=true` 按 `close_time <= now` 筛选；已到收盘时间但尚未最终确认的记录仍可在响应中出现。刚收盘目标根的等待状态由 `pending`/`finalized` 表示，返回窗口的确认状态由 `data_status` 表示。
- 等待预算从时间边界计算。只等待存在相应记录、尚未最终确认、且正在交易的序列；缺失记录不进入 pending。这保留了 Java 的行为，也意味着 pending 为空不等于历史数据完整。
- 0.4.11 将完整性诊断与上述 Java 字段分开。`closed_only=true` 响应增加 `data_status`：`window_finalized` 表示本次返回的所有记录均为 final，`nonfinal_symbols` 列出返回窗口中仍有未 final 记录的标的，`missing_latest` 列出已有历史之后缺少目标收盘根的标的。它不证明已返回请求数量的全部历史，也不证明内部没有缺口。空序列/首次上市前的根及固定周/月边界无法可靠推断的缺口不标记为 missing_latest。`closed_only=false` 不返回此扩展。
- 非交易状态的非最终记录进入 `not_trading`。目录支持动态刷新；下架会清除序列、释放等待并使响应缓存失效。
- 订阅通知后再检查状态，避免错过刚刚发生的最终提交。只有相关序列的状态变化会唤醒对应等待者。
- 相同 key 的请求共享一次等待、构建和编码。取消最后一个请求会清理在途 key；取消一个等待者不会破坏其他等待者。
- 只有 finalized 且返回窗口中所有记录均为 final 的 closed-only payload 可复用。缓存包含时间边界与最终修订版本，TTL=1 秒，最多 64 项、默认 64MiB。不同在途 key 默认最多 256 个，每个 HTTP 路由组默认最多同时处理 512 个请求；两处满了都先进入有界的先进先出队列等待，不再立即拒绝，排队数或等待时间超出上限才返回 503 -1008（见 runtime.md「诊断口径」）。

这些限制约束应用历史、缓存和正在处理的请求；生产连接数量与慢客户端超时仍应由反向代理和服务接入策略控制。

## 数值输出

数值策略属于 `kline-core`：double 使用 f64，float 直接解析为 f32 后以 f64 精确承载；输出沿用 Java 的 8 位小数上限、去尾零和负零规则。string 保存原始文本，bigDecimal 保存系数与 scale，输出遵循 `toPlainString`，比较也保留 Java 的 scale 语义。精确字段通过 Arc 共享；默认 double 路径不分配逐字段字符串或大数。异常时间、非有限浮点、超出 Java int 范围的成交笔数会被拒绝。

Java 21 `DecimalFormat` 使用旧版 `FloatingDecimal`，不同于 Rust 默认固定精度格式化。这里使用 Ryū 的短表示处理常见数值，在实际需要舍入时使用二进制 half-even，并处理旧版整数舍入及边界选择。极大值兼容路径使用栈缓冲区比较精确整数与舍入区间，没有引入大数堆分配。

兼容层通过 Java 原实现差分验证，包含 2 和 10 的幂及其相邻浮点数、随机有限位模式和小数舍入边界。格式化职责在 wire 模块，数值策略和等价比较在领域层。[JDK 对相关算法差异的说明](https://inside.java/2026/02/09/quality-heads-up/)。

`1w` 与 `1M` 时间边界保留 Java 的固定时长算法；日历月、周起点调整应作为独立业务变更评审。

## 后台与接口层

`kline-market` 负责独立的资金、元数据、ticker、统计和 CMS 服务。共享 REST 连接池按市场与资金费率分别限速；Moka 异步缓存合并同键加载，不在网络等待期间阻塞运行时线程。两个辅助 CPU 工作线程和 32 个任务名额承载大响应解析、目录整形、资金编码、ticker 帧解析、ZIP 和图像，等待名额也是异步的。bulk 编码由独立的专用线程和有界队列处理，默认两个工作线程；同一时间最多一个大任务，每八次小任务调度为大任务保留一次机会，不排在统计图之后。

目录用 ArcSwap 发布只读索引；更新时保留已有序列对象和 ID。连接按稳定 ID 分组，目录不变时不重建订阅表；新增或下架只重建受影响连接。逐主题停滞检查只对停滞主题发送 UNSUBSCRIBE/SUBSCRIBE 并要求该序列 REST 校验，不改变健康连接的 epoch 或其他序列的恢复进度。例行校验使用独立代数，已有有效数据继续服务；真实 gap/断线/过期仍使就绪失败。控制帧发送失败才重连；订阅效果依据实际数据到达和 REST 覆盖验证。

实时 ticker 合并不接受旧 closeTime 覆盖新记录；全市场响应字节缓存 500ms，REST 定期提供基线，WS 更新最新值。合约使用 !ticker@arr；现货按交易目录订阅逐标的 @ticker，每连接最多 200 个主题，每 60 秒协调目录。资金请求的小时切片和近期结果分别缓存；:05 使当前切片与近期版本失效。Vision 的 404 缺档不使其他标的失效；真实下载或档案级解析失败仍阻止整月发布，保留 REST 补查。坏 CSV 行单独跳过。

## 兼容边界

27 个 Java 业务操作均已实现。普通 Kline 默认只查本地缓存，spot timeZone/1M 转发上游，保留 Java 的行为；请求过程中不会悄悄为普通查询冷加载整个历史。统计数值按实际 Java 类差分检查；PNG 提供相同数据与标题，使用内置字体重新绘制，0.4.12 起尺寸对齐为 1024 × 768，不追求 Java Chart 的逐像素复制。普通 Kline 的非正 limit 在 Rust 中钳制为 1，Java 当前会返回 500；多币 price 的行顺序在 Rust 中跟随请求，在 Java 中跟随上游。调用方应按 symbol 匹配行。

四种数值模式贯通 WS、REST、补位、查询、统计、快照与 Java 快照导入。非法配置会拒绝启动；上游非预期故障返回结构化 502，某些校验错误的 message 文案不保证逐字一致。Prometheus 提供 Rust 的实际计数和 HTTP histogram，保留采集路径；不伪造 JVM/GC/JIT 指标，旧 JVM 专属面板需更新。

0.4.11 的共享 HTTP 输入层兼容可选空数字、JSON 字符串数字与 null/空 body，以及 Spring 查询参数的 true/false、on/off、yes/no、1/0。JSON body 的 Boolean 转换独立于查询转换。bulk 空 body/null 仍返回 JSON 400/-1102；funding bulk 使用默认查询。格式错误返回 JSON 400/-1100，超长 body 保留 413、错误媒体类型保留 415，均提供 code/msg。旧 Java 对部分非法绑定返回 500 的行为没有复制；上述合法旧请求和业务字段已用当前 Java 控制器差分验证。

内存与磁盘容量分别限制。配置转换器保留 Java 启用持久化时的有效历史深度。Rust 严格容量、窗口边界、只读导入与损坏跳过规则见运行文档。旧性能实验不含所有新后台链路，生产性能需通过同环境、同流量的逐小时对照确认。

全市场 ticker/price 独立使用价格端点与 ArcSwap 字节快照。首次加载合并并发请求，热请求直接复用已发布字节；后台在最近 5 秒有访问时以 500ms 为 REST 刷新目标，独立发布任务约每 100ms 合入有效 WS 数据。编码快照上限 250ms、REST 基线上限 10 秒，超过后需刷新；行情查询总预算 5 秒。24hr 的部分 WS 增量不会被误认为完整 REST 基线。无筛选的缓存查询不再逐次扫描全市场元数据。单币价格和 24hr 查询优先使用有效 WS 观测，未命中再使用 REST，并允许等待期间的 WS 更新直接完成请求。
