另外保留了一组全部新建 TLS 连接的测试，每服务 2000 次，数据逐对一致、零请求错误。原始端到端 p99 为 Rust 453.33 ms、Java 382.33 ms。但测试机 Go 进程在 Rust 波次占用约 193%～199% CPU，在 Java 波次约 175%～197%，已接近其两颗 vCPU 的极限；同组 Rust Nginx 收到 HTTP 后的 request_time p99 仅 19 ms。握手/客户端调度构成测量瓶颈，因此这组数字不能作为 Rust 引擎退化或真实 200 个独立 Lambda 的延迟估计，也不能据此断言所有新连接开销都来自客户端。原始样本完整保留，没有并入复用连接结论。下一步若测真实冷启动，应先扩充分布式压测能力并同步采集服务端 TLS/CPU 指标。
