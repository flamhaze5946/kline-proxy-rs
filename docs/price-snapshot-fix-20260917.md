**Rust 0.4.5 全市场价格修复与部署记录**

2026-09-17 09:38:25 UTC 部署至 `192.0.2.40` / `market-mirror.feng.dog`。Java 实例保持原版本作为对照。本次只修改 Rust 全市场价格的缓存、编码和后台调度路径，单币行情、K 线容量、REST 权重和全局额度保持原设置。

此前的问题有两部分：全价列表要求每行都有 3 秒内的 WS 值，实际却包含大量不订阅 WS 的非交易币对；一旦 REST 基线超过 3 秒，前台会等待正在进行的 REST 刷新。同时响应缓存每 100ms 失效，前台重新遍历、复制并编码整个列表。全量 24h ticker 刷新与价格快照维护还在同一异步循环里，前者的等待会推迟后者。

修复后，24h 基线维护、价格 REST 刷新和价格快照发布独立运行，并统一响应服务停止信号。活跃访问时，完整 REST 列表约每 500ms 刷新，发布任务约每 100ms 合入有效 WS 观测并预编码；正常查询直接复用不可变响应字节。编码按市场批量取得读锁，直接借用行内容序列化，避免逐币加锁和复制 JSON 树。停牌及元数据缺失币对继续留在 REST 定义的返回集合里，不作为 WS 完整覆盖的前提。冷启动并发请求共用一次加载。

**新鲜度取舍是明确的行为变更。** 全市场 REST 基线的硬期限从原来的 3 秒等待门槛改为 10 秒；后台目标仍是 500ms 刷新，WS 覆盖的行继续更新，未覆盖的行在排队时允许使用这段宽限内的 REST 值。预编码响应最长使用 250ms。超过 10 秒必须刷新，沿用查询总时限 5 秒及超时 503，重新编码不会重置 REST 年龄。单币接口的 3 秒 WS 条件不变，因此不能把所有全价延迟改善描述成等新鲜度的计算加速。

新增 `/health/market` → `tickers.future/spot.price_snapshot`：包含完整行数、合入 WS 的行数、REST 年龄、编码年龄、编码所用 REST 年龄、硬期限，以及加载/发布次数。

83 项 Rust 测试、7 项配置转换测试、格式检查、Clippy 禁止警告、macOS 与 Linux release 构建通过。新增回归覆盖超过 3 秒的阻塞刷新期间继续返回并更新 WS、停牌和未知币对保留、32 个冷请求共用一次 REST，以及重复编码不能延长过期基线的期限；已有精度、合约 v2 路径、成交时间、断线和取消测试继续通过。
