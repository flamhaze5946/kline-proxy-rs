# Rust 单币价格复用本地 K 线

0.4.16 将现货 `/api/v3/ticker/price?symbol=...`、合约 `/fapi/v1/ticker/price?symbol=...` 及现货仅选择一个 symbol 的数组查询调整为：有效 WS 行情 → 本地实际 K 线最新 close → 原有 REST 缓存/加载。

## 行为与边界

- WS 仍保留原来的连接、3 秒新鲜度及合约成交时间顺序检查。
- WS 不满足读取条件时，按订阅配置顺序查找全部周期；首个周期缺失或尚未初始化，继续尝试后续周期。静态配置的周期追加在订阅周期之后，同市场去重；空配置默认 1h。
- 通过 catalog 的索引定位 symbol/interval，仅在序列读锁内读取和编码最新 close，不扫描全市场、不复制 K 线窗口、不增加价格副本或后台任务。
- 本地实际记录存在即使用，不因年龄额外触发价格 REST。断线时可能返回最后已知价格，与 Java 1.8.3 的缓存优先策略一致。这不是对币安即时价格完全相同的保证。
- 本地读取在原有 500ms REST 单币缓存之前，因此新 K 线 close 不受该缓存 TTL 限制。现货不输出 time；合约本地价格沿用 Java 的查询时刻，WS/REST 返回各自真实成交时间。本地查询时刻不写入 REST 时间门槛，不会阻止随后到达的 WS 成交价格。
- 取价只读实际记录，不构造或持久化 K 线，也不改变原有补零授权。缺少当前 bar 时可读上一根 close；构造当前零成交量 bar 仍必须收到紧邻上一根 WS `x=true`，并且不得把占位当作已收盘数据。
- 所有配置周期都没有本币种数据时，保留原来的 REST 路径、权重、500ms 缓存、错误转换和 5 秒总时限。HTTP 币种校验、现有参数语义保持一致；元数据首次加载或超过原有宽限仍可能访问 exchangeInfo。
- 全市场价格、多币种列表及 24h ticker 沿用原有策略；合法空列表的兼容回退仍只选配置的第一个周期。

`/health/market` 的 `tickers.future/spot.kline_price_hits` 记录本地 K 线命中。结合 `live_query_hits` 与 `single_rest_loads` 可以核实请求走向；后两者包含 24h ticker，应在明确负载范围内解释增量。

## 验证

新增 HTTP 回归覆盖双市场、四种数值模式、过期 WS、阻塞的价格上游、跨周期读取、市场与币种隔离、新 K 线覆盖已缓存 REST 值、WS 优先级及 `x=true` 条件不被放宽。原有 REST DTO/错误测试改为明确的无 K 线缓存场景，继续验证真实缺失时的错误传播。

179 项 Rust 测试、8 项配置转换器测试全部通过，Clippy（warnings 作为错误）和格式检查通过；Linux x86_64 release 构建通过。原始日志和部署前后使用相同请求矩阵的东京测试脚本保存在 [验证目录](../research/results/single-price-memory-20260929/)。线上激活和测试结论以该目录记录为准。
