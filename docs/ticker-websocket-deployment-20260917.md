价格及单币 24h ticker 现在优先读取新鲜的 WebSocket 观测。东京测试机的 160 次正式查询全部成功、全部命中 WebSocket，期间单币 REST 加载计数增量为 0；应用日志也没有 ticker REST 取得额度或缓存加载记录。此前 0.4.3 已复现的 10–60 秒 REST 排队长尾，在这次短测中没有出现。两次测量窗口和修改范围不同，不能据此计算严格的整体加速倍数或生产 p99。

**本次行为与保护措施**

| 功能 | 数据来源与行为 |
|---|---|
| 合约、现货单币 24h ticker | 读取已有 ticker WebSocket 观测 |
| 现货最新价格 | 使用 ticker WebSocket 的 `lastPrice`，保留字符串精度 |
| 合约最新价格 | 按需订阅 `aggTrade`，使用成交价格 `p` 与成交时间 `T`；不把 ticker 的统计结束时间当成交时间 |
| 全市场最新价格 | REST 建立完整列表，再覆盖新鲜 WebSocket 数据；未覆盖、冷启动及过期数据仍保留 REST 补充 |
| REST 等待期间收到新行情 | 当前查询立即使用合格的 WebSocket 数据，取消自身的回退等待 |
| 新鲜度与断线 | 事件时间及接收时间均限 3 秒，断线立即使该连接的观测失效；合约 WS 成交时间必须晚于已观察到的 REST 时间 |
| 合约成交订阅 | 按查询需求建立，空闲约 5 分钟后由监督循环移除；全市场价格查询会暂时订阅全市场合约成交 |
| REST 回退保护 | 使用公平、可取消的 FIFO 排队，保留市场共享权重及冷却；ticker 查询总时限 5 秒，包含元数据、排队、重试和 HTTP，超时返回 503 / -1008 |
| 元数据校验 | 周期刷新进行中可使用有限时间内的成功快照，仍校验币种与状态 |

HTTP 路径、响应字段及小数精度保持兼容；合约价格的 REST 回退仍调用 `/fapi/v2/ticker/price`。Java 生产实例未部署变更。K 线配置文件 SHA-256 与发布前一致，仍保留 1h 容量 1001、1d 容量 2001（包含当前未收盘位置）。

另外 32 次最近 10 根 K 线请求全部成功：合约及现货各 8 次普通查询、8 次 BTC/ETH bulk 查询。16 对 BTC 结果的完整 10 根数组哈希全部一致，最后一根为 07:00 UTC 开盘、07:59:59.999 UTC 收盘；bulk 均 `finalized=true`、`pending=[]`、`waited_ms=0`。合约/现货普通接口中位数分别 1.28/1.22ms，bulk 分别 1.36/1.37ms。额外读取两市场各 1000 根 1h、2000 根 1d 已收盘数据，数量均完整。

128 次合约 bulk 检查使用 32 个交易币种、每币 10 根、并发 16，128/128 成功且完整收盘，中位数 10.13ms、样本 p99 71.24ms、最大 71.61ms。p99 使用最近秩法；此段包含新连接建立，仅是有界诊断突发，不是生产整点 p99。

全市场价格单独在上述单币采样之后检查，避免全市场成交订阅干扰单币结果：合约首次 446.68ms、第二次 4.66ms，返回 766 行；现货首次 33.37ms、第二次 7.14ms，返回 3708 行。合约首次加载的日志显示本地额度等待 433.42ms、Binance HTTP 3.69ms，首次尝试成功、无冷却。后续未被 WS 完整覆盖的币种仍由后台 REST 维护，因此“单币正式样本零 REST 回退”不等于所有后台 REST 已停止。

全部探针及一次 exchangeInfo 请求对应 338 条 Nginx 记录，全部 HTTP 200。08:12:46–08:13:06 的独立 20 秒资源采样中，全市场成交订阅仍活跃，应用平均 CPU 15.74%（100%=一个 vCPU）、RSS 710.85MiB；Nginx CPU 增量低于该采样分辨率。这不是测量期间 CPU，也没有同负载旧版对照，不能用于判断 CPU 或内存改善幅度。

部署后日志中有 7 条启动阶段 Binance 历史资金费率归档 HTTP 503；本次 ticker 正式采样期间未见 ticker WS 错误或上游 429/418。本报告验证范围为此次行情读取改动、相关 K 线回归及部署健康，不代表全部功能的长期可用性验证。
